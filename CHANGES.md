# CHANGES: absence/timing tools (2026-11-22)

## What changed

- `agent/tools.py`: three new tools, bound to the incident's session like the existing ones:
  `find_missing_response(trigger_msg, expected_msg, window_s)`,
  `gap_vs_timer(event_a, event_b, timer_name)`, `last_event_before(t, layer)`.
  Every message they mention is an evidence object with `line_id` (`"<LAYER>@<ts>"`),
  layer, ts, msg_type, direction and fields, so citations go through the unchanged verifier.
  `TIMER_TABLE` comes from the spec timer definitions: T300 1 s, t304 (the logged `t304_ms`,
  else 1 s), T3510 15 s, T3513 2 s (network-dependent in the spec; 2 s is also the
  synthesizer's value), T3560 6 s.
  Deviation from the brief: the `ue_id` argument is accepted and ignored. The tools are
  bound to the incident's session, like `get_*_window`, so it isn't in the LLM-facing schema.
- `agent/investigator.py`: `investigate(..., toolset="v1"|"v2")`. v1 is the old prompt and
  four tools, unchanged. v2 adds the three tools and one prompt paragraph about absence
  evidence, with no fault-type names; a test enforces this. The final-answer schema,
  `insufficient_evidence` flag, `num_predict=400` and the 10-step budget are unchanged.
- `tests/test_absence_tools.py`: 26 tests on fixture logs. Negative cases include: answer
  present, answer outside the window, no trigger, window not fully logged, a gap that does
  not match the timer, unanswered but log too short to claim expiry, unknown timer, strict
  "before", empty layer, bad layer. Other tests: every evidence object passes the citation
  verifier, the prompt and tool descriptions contain no fault-type names, v1 is unchanged.
- `eval/run_eval.py`: `--agent`, `--data-dir`, `--out-dir`, `--model`, `--fault-types`;
  writes `run_config.json`; records `insufficient_evidence`.
  `eval/report.py` takes an output directory.
  `eval/compare.py` (new) builds all before/after tables with k/n, an exact McNemar test,
  and a count of final answers cut off by the token cap.
- `data_heldout/`: seed 20261122, generated by the unchanged generator and frozen before
  any agent change. Hashes are in `eval_results/heldout_manifest.json`; it has 0 incidents
  in common with the original set.
- Makefile targets: `data-heldout`, `eval` (v2, original), `eval-heldout`, `eval-v1`,
  `eval-7b`, `eval-compare`, `test`. The parser and synthesizer are untouched.

## Results (qwen2.5:3b-instruct, identical settings old vs new)

| | original: old | original: new | held-out: old | held-out: new |
|---|---:|---:|---:|---:|
| accuracy | 23/86 | 14/86 | 26/85 | 11/85 |
| citation hallucination | 48/86 | 54/86 | 41/85 | 49/85 |
| final JSON cut off (400-token cap) | 19/86 | 36/86 | 14/85 | 32/85 |
| avg tool calls | 1.80 | 2.83 | 1.98 | 2.89 |
| three previously-0% types | 1/27 | 3/27 | 1/27 | 0/27 |

- Paired McNemar on accuracy: original p = 0.093 (16 regressions, 7 fixes); held-out
  p = 0.0015 (18 regressions, 3 fixes).
- The published September v1 run scored 22/86; the v1 re-run scored 23/86.
- On the 27 original-set incidents of the three types:
  - 7B with the new tools: 1/27, hallucination 21/27.
  - 7B with the old tools (Part 3): 0/27.
  - 3B with the new tools: 3/27.

**The change made the agent worse.** The tools return correct absence evidence: replaying
the 26 paging/registration absence checks the agent made, all 26 returned
`any_missing: true`. The model named the right fault in only 1 of those 22 investigations.
Of the regressions, 9/16 on the original set and 11/18 on held-out are final answers cut
off by the unchanged token cap.

## Correction to an earlier claim

The README said "20 of 86 investigations honestly set `insufficient_evidence: true`". All
20 were the fallback written when the final JSON failed to parse because it was cut off by
`num_predict=400`; the model set the flag itself 0 times in that run. The README now has a
dated correction note under that paragraph (original text kept).
